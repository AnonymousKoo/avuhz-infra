## Explicitly identified security gap

The ledger policy checks `current_setting('avuhz.handoff_claim_tenant', true)`. The PostgreSQL GUC **is caller-settable** and does **not** independently authenticate the tenant, owner, GitHub runner, or signed authorization. Further, the adapter's `current_user = 'avuhz_handoff_claim_writer'` and RLS catalog checks prove narrow SQL permissions but **not** who supplied the connection or whether a valid owner authorized its use.

**Therefore no runner should receive `SET avuhz_handoff_claim_writer` membership or a reusable writer credential solely because the table passed RLS tests.** Before credential access, the bound executor must prove trusted GitHub event/repository/actor/main, owner-key enrollment from a distinct trusted channel, all four fresh valid source/tenant/project/payload-bound signed stage plans, and a pristine once-only scope. A connection that can freely claim other tenants without verified owner controls is a hard stop for real-client use; this plan targets only a fictional DEVELOPMENT handoff.
