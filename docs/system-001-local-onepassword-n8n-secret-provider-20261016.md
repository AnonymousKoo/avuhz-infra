## Adapter behavior

- Caller must explicitly specify `environment="LOCAL"` or `"TEST"`, and the **independently reviewed and authorized** 1Password vault/item/field stable-ID reference as three slash-delimited ASCII segments with the `op://` scheme. There is no default reference, fallthrough to another vault, search or item enumeration. It rejects query strings, shell metacharacters, unexpected segments and newline characters.
- Each requested delivery calls exactly **one** `op read --no-newline` subprocess (no shell or retries) in an already approved **signed-in** owner session. The secret returns only inside a child-process stdout pipe to the trusted caller's memory. No file, provider stdout forwarding, logs, shared environment-variable values, credentials in argv, vault discovery, 1Password sign-in prompt, or clipboard.
- Fail closed on unavailable/locked account, timeout, nonzero exit status, invalid token, disallowed environment or CI. Accept only printable ASCII 32–512 bytes; output remains the existing receiver/sender header secret and is never sent elsewhere by the adapter. The existing sender rejects/catches failures with its safe retry category.
- The adapter is not a credential issuer, browser flow, deployment, n8n credential import, n8n workflow binding, standalone sender or lifecycle supervisor. The caller is still responsible for a private environment, approved tenant/identity, canonical outbox and verified HTTPS URL/TLS context; n8n can only respond with successful **202** after a separately authenticated durable receipt.
- Tests use ephemeral in-memory synthetic tokens and a mocked CLI. No real 1Password call or secret value occurs in tests. All seven focused tests cover invalid references, LOCAL-only/CI gating, exactly-one no-shell subprocess and timeout handling, safe failure, and compatibility with the actual `N8nOutboxSink` and its strict 202 requirement.
